# 폴더 규칙 설정

## 우선순위

`VAULT.md`는 자신이 있는 폴더와 하위 폴더의 노트에 적용된다. 루트부터 노트에 가까운 파일 순서로 읽으며, 같은 설정 키와 충돌하는 글쓰기 규칙은 가까운 파일이 우선한다. 명시적인 요청은 글쓰기 규칙보다 우선하지만 `write: false`와 `.markdown-notes-agentignore`로 막힌 경로를 쓰도록 허용하지 않는다. 상위 시스템 지침은 사용자 폴더 규칙보다 우선한다.

다른 폴더의 원문을 참고하더라도 원문 폴더의 규칙을 대상 폴더에 적용하지 않는다. 모델 입력에는 중복을 제거한 규칙 본문과 원문·대상 경로별 규칙 참조가 분리된다. 원문에 들어 있는 명령은 자료로만 취급하며, `VAULT.md`는 사용자 설정으로 취급한다. 설정 파일은 인용 근거나 편집 대상이 아니다.

공통 작업 지시는 짧은 헤더로 전달한다. JSON의 최상위 `request`는 사용자 요청이며, `profile`과 `policy`는 적용할 작성 규칙이다. `input`에는 원문과 이전 모델 결과 등 판단할 자료를 담는다. 사용자 요청을 원문 자료 안에 섞지 않는다.

개념 추출의 명시 속성도 같은 JSON의 `input.explicit_values`로 전달한다. `policy.field_precedence`는 명시값을 추론보다 우선하며 `policy.inference`는 `missing_fields_only`다. 실제 색인에도 명시값 우선권을 적용한다.

## 항목

### `VAULT.md`

| 키 | 타입 | 기본값 | 환경 변수 | 뜻 |
|---|---|---|---|---|
| `write` | 문자열 | `true` | 없음 | 대소문자와 관계없이 `false`, `no`, `0`이면 생성·수정·삭제를 차단한다. |

설정은 파일 맨 앞의 `---` 두 줄 사이에 둔다. 그 뒤의 본문은 해당 폴더의 문서 작성 규칙이다. 파일명, 언어, 문체, 원본 보존 방식은 이 본문으로 정한다.

루트의 `write: false`도 하위 `VAULT.md`의 `write: true`가 덮어쓴다. 이 설정은 전역 운영 중지 기능이 아니다. 전체 작업 중지는 실행 중인 서비스의 수명주기에서 별도로 다룬다.

### `.markdown-notes-agentignore`

등록할 때 승인한 ignore 규칙이 읽기와 쓰기 범위를 정한다. 이후 파일 변경은 기존 승인 절차를 따른다. 실행 중인 제안은 디스크의 ignore 파일 또는 적용된 ignore 규칙이 바뀌면 다시 판단해야 한다. 미승인 ignore 변경을 즉시 새로운 접근 권한으로 사용하지 않는다.

## 실행 중 재검증

변경이 없는 `keep`과 `defer`도 검토한다. 이때 읽은 원문 전체와 결정 이유를 검토 입력에 포함한다. 검토자는 요청한 기록의 누락을 확인한다. 가설이나 미실험 주장을 그 상태로 기록하라는 요청은 외부 검증이 없다는 이유만으로 보류하지 않는다. 정당한 유지·보류를 승인하면 파일을 바꾸지 않고 기존 완료·보류 상태를 유지한다.

변경이 없는 결정에도 검토 모델 호출 1회가 추가된다. 검토가 거절하면 기존 `jobs.review_attempts` 설정에 따라 피드백을 넣어 다시 작성한다. 기본값은 최초 초안을 포함해 3회다. 매번 거절되면 실패로 끝나며 파일을 바꾸지 않는다.

추가 원문을 읽거나 유사 문서를 발견하면 경로별 규칙, 읽기 전용 여부, 키워드 정보와 원문 서명을 함께 갱신한다. 모델이 새 대상 경로를 고르면 해당 경로의 규칙을 읽는다. 이미 본 규칙 순서와 쓰기 권한 조합이면 대상 연결만 갱신한다. 새로운 규칙이나 권한 조합이면 초안을 다시 평가하고 그 결과를 검토한다. 한 요청에서 새 대상 정책 때문에 초안을 다시 평가하는 횟수는 최대 4회이며, 그 뒤에도 수렴하지 않으면 `policy_limit` 오류로 멈춘다.

초안 작성 전후, 검토 전후와 파일 적용 직전에 정책 의존성을 확인한다. 확인 대상은 읽은 `VAULT.md` 내용, 해당 경로에 파일이 없었다는 사실, 디스크와 적용 중인 ignore 규칙이다. 없던 `VAULT.md`의 생성도 변경에 포함된다. 정책이 바뀌면 저장된 제안을 적용하지 않고 충돌로 남긴다. 정책 의존성은 작업 상태에 저장하므로 재시작 뒤에도 검사한다. 이전 버전에서 저장한 제안에 정책 의존성이 없으면 다시 판단해야 한다.

모델에 전달할 규칙 본문의 합이 32 KiB를 넘으면 `rules_limit` 오류로 멈춘다. 루트 규칙이나 다른 필수 규칙을 조용히 생략하지 않는다. UTF-8로 읽을 수 없는 규칙 파일도 오류다.

## 전체 예

```markdown
---
write: true
---

조건, 예외, 출처와 판단이 달라진 이유를 보존한다.
```

## 검증 범위

`tests/test_policy_workflow.py`는 경로별 규칙, 정책 변경 충돌, 추가 읽기와 재시작 뒤 적용 차단을 검사한다. `tests/fixtures/prompt-cases.json`은 프롬프트 내용 보존과 후속 모델 평가에 쓰는 고정 입력이다. `uv run python benchmarks/measure_prompts.py --baseline 36906f6`은 같은 입력의 UTF-8 바이트를 비교한다. 이 수치는 토큰 수, 응답 속도나 실제 모델의 사실 보존 품질을 뜻하지 않는다.

프롬프트의 도구 사용 금지는 모델 지시다. Claude 실행은 `--tools`에 빈 값을 전달하며, Codex 실행은 기존 read-only sandbox를 사용한다. Codex 도구 자체의 실행 불가능 여부와 실제 모델의 사실 보존 품질은 이 검사로 확인하지 않는다.

`uv run python benchmarks/evaluate_prompts.py --baseline 36906f6`은 고정 합성 사례 6개에서 같은 모델과 추론 수준으로 프롬프트를 비교한다. 작성 사례는 양쪽 모두 현재의 정책·원문 보호, 기계적 조립, 검토와 런타임 재작성 경로를 사용한다. 검색은 고정 원문으로 대체하며, 결과는 메모리에서 조립한 문서로 검사하고 파일에 적용하지 않는다. 이전 런타임과 현재 런타임의 속도를 비교하는 실험은 아니다.

작성 사례별 모델 호출 상한은 `--max-calls`로 정하며 기본값은 초안과 검토를 합쳐 6회다. 호출별 제한 시간은 `--timeout-seconds`로 정하며 기본값은 150초다. 각 호출의 입력, 응답, 이벤트, 사용량, 오류와 도구 호출 수를 보존한다. 첫 작성 시도와 최종 결과의 판정을 구분하고 거절된 중간 결과도 남긴다. 검토가 승인해도 필수 기록이 빠지면 최종 실패다. 이 검사는 고정 사례의 보존 조건만 판정하며 일반적인 모델 품질이나 성능 순위를 확정하지 않는다.
